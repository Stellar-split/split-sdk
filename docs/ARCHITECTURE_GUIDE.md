# StellarSplit SDK — Detailed Architecture & Extension Guide

This guide complements [`ARCHITECTURE.md`](../ARCHITECTURE.md) with deep-dive subsystem specifications, data-flow invariants, and programmatic architecture introspection via `src/architectureRegistry.ts`.

---

## 1. Subsystem Boundaries & Invariants

### 1.1 Invoice State Machine (`src/state/InvoiceStateMachine.ts`)
All invoice lifecycle transitions are validated prior to network submission:
- `DRAFT` -> `PENDING` (on `createInvoice`)
- `PENDING` -> `PARTIALLY_FUNDED` (when `0n < paidAmount < totalAmount`)
- `PENDING` | `PARTIALLY_FUNDED` -> `FUNDED` (when `paidAmount >= totalAmount`)
- `FUNDED` -> `RELEASED` (when split distribution completes on-chain)
- `PENDING` | `PARTIALLY_FUNDED` | `FUNDED` -> `DISPUTED` (when a dispute is opened)
- `PENDING` | `PARTIALLY_FUNDED` | `DISPUTED` -> `REFUNDED` (when funds are returned to payers)

### 1.2 Split Allocation & Rounding Invariant (`src/paymentAllocation.ts`)
For any invoice total $T \in \mathbb{Z}_{\ge 0}$ and recipient basis-point weights $w_1, \dots, w_n$ where $\sum_{i=1}^n w_i = 10000$:
1. Each recipient $i$ receives floor allocation $a_i = \lfloor (T \cdot w_i) / 10000 \rfloor$.
2. The deterministic remainder $r = T - \sum_{i=1}^n a_i$ (where $0 \le r < n$) is distributed 1 stroop at a time according to the configured rounding policy, guaranteeing $\sum_{i=1}^n a'_i \equiv T$ with zero lost stroops.

### 1.3 Error Taxonomy & Recovery (`src/errors.ts`)
All errors thrown by the SDK inherit from `StellarSplitError` and provide:
- `code`: Machine-readable identifier (e.g., `INVOICE_NOT_FOUND`, `SIMULATION_FAILED`, `CIRCUIT_OPEN`).
- `retryable`: Boolean flag consumed by `executeWithRetry` (`src/retryPolicy.ts`) and `CircuitBreaker`.
- `suggestions`: Actionable remediation guidance generated by `src/errorSuggestions.ts`.

## 2. Programmatic Architecture Introspection

Tools, documentation generators, and integration tests can inspect and validate the SDK's architecture at runtime using `ArchitectureRegistry` (`src/architectureRegistry.ts`):

```typescript
import {
  ArchitectureRegistry,
  validateArchitectureCatalog,
} from "../src/architectureRegistry.js";

const registry = new ArchitectureRegistry();
const report = validateArchitectureCatalog();

if (!report.valid) {
  throw new Error(`Architecture drift detected: ${report.errors.join(", ")}`);
}

console.log(`Validated ${report.layerCount} layers and ${report.extensionPointCount} extension points.`);
```
